Module 1 · Docker foundations and first container

What Docker is and why containers matter

Understand how containers package apps and why they improve portability.

Containers package an application with everything it needs to run, so it behaves the same on your laptop and in production.

Learning points

  1. Understand the difference between containers and virtual machines.
  2. See how containers improve portability and consistency.
  3. Know when Docker is a good fit for a project.

Lesson notes

Before Docker, "it works on my machine" was a common problem because development and production environments drifted.

A container shares the host kernel but packages its own filesystem, libraries, and dependencies.

Containers start quickly and use fewer resources than full virtual machines, making them practical for local development and deployment.

Example

bash
docker run hello-world
# Expected output explains that Docker pulled and ran a tiny image.

Practice

  1. Read the Docker overview page and list three problems containers solve.
  2. Compare a VM diagram with a container diagram.
  3. Explain to a teammate why a container is lighter than a VM.

Reasons & Mistakes

Good reasons
  1. Consistent environments reduce deployment surprises.
  2. Lightweight containers make scaling and local testing cheaper.
Common mistakes
  1. Treating Docker as just a packaging tool without understanding the runtime model.
  2. Running every service in a container when a simple binary or script is enough.

Takeaways

  1. Docker uses containers to package apps with their dependencies.
  2. Containers improve consistency between development and production.
